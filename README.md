[English](README_EN.md)

给 AI 一个还不完整的需求，让它从真实的消费者表达、行为和选择中找线索，讲清楚为什么，最后给出朴实、锐利、尽量简短的洞察。

`songyue-insight` 是宋玥的消费者洞察挖掘 Agent Skill。它重点解决两个问题：AI 容易把几条帖子概括成所有消费者，也容易把洞察写成漂亮话，或一路扩展成策略方案。

这个 Skill 把工作重点放在 **现象 → 关键推导 → 洞察**。既不只交付几句结论，也不默认展开完整营销策略。

本项目与宋老师的营销诊断技能沿用同一套实践取向：重视具体事实、推导过程和真实商业问题。两者分工不同——营销诊断检查方案卡在哪里，洞察挖掘先帮助理解消费者为什么这样选择。本技能可以独立使用，不依赖其他仓库。

## 适合什么任务

- 客户给了一个模糊需求，需要先查产品、品类或人群的消费者洞察。
- 已经看到一些用户评论、购买行为或市场现象，需要判断背后是什么原因。
- 手里有一句“洞察”，想检查它究竟是洞察、现象、常识，还是文案。
- 需要为后续方案准备有来源、有推导、有适用边界的消费者判断。

信息不全也可以开始。只有缺口会让研究方向完全改变时才追问，其他情况会说明临时假设，继续检索。

## 怎么唤醒

安装后，可以直接说：

```text
帮我查一下新鲜零食的消费者洞察。
```

```text
我们在做一个保险品牌的客户口碑传播，帮我挖掘相关消费者洞察。
```

```text
这个产品有什么消费者洞察？先看用户的实际购买和使用经历。
```

```text
帮我判断这句话是不是洞察：……
```

想明确指定时，可以说：

```text
使用 songyue-insight，帮我查一下这个品类的消费者洞察。
```

在支持 `$技能名` 的环境里，也可以使用 `$songyue-insight`。

## 会得到什么

开放式挖掘以至少两个有依据、互不重复的洞察为目标，证据充分时三个、四个都可以；证据不足就说明缺口，不凑数量。判断用户提交的一句话时，不套用数量要求。

每条保留三个部分：

1. **现象**：消费者具体说了什么、做了什么、放弃了什么，并附来源。
2. **关键推导**：最容易得到的解释为什么还不够，这些事实还说明了什么。
3. **洞察**：收成一个朴实、锐利、尽量简短的判断，必要时紧跟适用边界。

有价值但只适用于局部场景的发现，可以单列“值得单独看的补充判断”。策略不是必答题；确有直接启发时，全篇附一两句即可。

简短是表达偏好，不是硬字数限制。不能为了短，把判断的来路删掉。

## 它怎样找证据

- **按问题选平台**：先看人群、购买角色、消费阶段和要找的信号，不让所有品类都只搜小红书或行业报告。
- **正文与评论一起看**：关注具体经历、追问、反对和失败；不把评论区天然当成更真实的地方。
- **正反两面都找**：除了喜欢和购买，也看不买、退货、不复购、替代品和使用代价。
- **把证据分开**：消费者自述、品牌选编案例、媒体报道、行业数据和研究者解释，不能混成“网上都这么说”。
- **不以偏概全**：区分品类中的重要机制与局部场景，不把一次送礼、一次理赔或一条高赞评论当成所有人的动机。
- **证据不足就停**：可以只确认现象，或者标为待验证假设，不为了完成输出编造洞察。

## 安装与使用条件

本仓库提供 Agent Skill 文件，不是独立网站，也不包含模型账号、搜索服务或平台登录凭据。实际检索由宿主 Agent 已有且获授权的工具完成。

下载仓库 ZIP，或克隆：

```bash
git clone https://github.com/83songyue/songyue-insight.git
```

导入或复制仓库里的 **`songyue-insight/` 子文件夹**到支持 Agent Skills 的工具中，保留其中全部文件。不要只复制 `SKILL.md`，也不要把仓库根目录误当成技能目录。已有同名技能时，先备份或确认更新，不直接覆盖。

Codex、Claude Code 及其他兼容环境的安装入口以各工具为准；名称、说明和提示词可能以不同方式显示。

要执行“查、搜、挖掘”，宿主需要具备联网检索或读取用户材料的能力。没有某个平台的访问权限时，应明确说明，并寻找同类替代证据；没有联网能力时，仍可基于用户提供的材料做判断，但不能声称已经搜过。
